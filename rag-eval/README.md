# 법령 검색(RAG) 평가 — 정답 묶음 100문 · 채점 스크립트 · 실측 결과

> **English summary.** Evaluation material for the legal-search (RAG) part of SafeLedger: a 100-question golden set (70 answerable, 52 of them with expected articles; 30 that must stay unanswered), the scoring script, the threshold probe, and the numbers we measured. The first 40-question draft looked fine (expected-article top-5 hit 12/13, silence 12/12). The harder 100-question set did not: top-5 hit 36/52, silence 16/30. These are retrieval-stage metrics, not final-answer accuracy. The search API server is not in this repository, so the scripts cannot be run from here; what you can check is the question set, the scoring logic and the recorded results.

SafeLedger 의 법령 질의응답은 산업안전보건 법령·고시·판례를 검색해 근거를 붙여 답합니다.
이 폴더는 그 **검색 단계**를 어떻게 쟀는지를 옮긴 것입니다.

| 파일 | 내용 |
| --- | --- |
| `golden-100.json` | 정답 묶음. 답이 있는 질문 70(그중 기대 조문이 적힌 것 52) + 답하지 않아야 하는 질문 30 |
| `rag-score.mjs` | 채점 스크립트. 찾음 · 기대 조문 Top-N 적중 · 침묵을 세고, 어느 검색 경로가 낸 점수인지 함께 적는다 |
| `rag-recall-probe.mjs` | 임계값을 0 으로 한 번 돌려 점수를 전부 받아 두는 탐침. 임계값별 적중은 그 결과에서 산술로 낸다 |

정답 묶음과 스크립트는 제 계정 커밋에서 왔고, 스크립트는 Claude Code 와 함께 썼습니다.
무엇을 잴지(무응답 문항을 넣을 것, 적중과 침묵을 함께 볼 것, 경로별로 가를 것)와 결과를 보고 내린 판단은 제가 했습니다.

## 여기서 확인할 수 있는 것과 없는 것

- **확인할 수 있는 것**: 문항과 기대 조문, 채점 규칙(코드), 아래 결과 표.
- **확인할 수 없는 것**: 검색 API 서버와 법령 색인은 팀 비공개 저장소에 있어 이 저장소만으로는 스크립트를 돌릴 수 없습니다. 아래 수치는 당시 실행 기록을 옮긴 것이고, 원본 로그는 여기에 없습니다.
- 발췌하면서 바꾼 것: `rag-score.mjs` 의 로그인 부분을 환경변수(`QA_BASE` · `QA_TOKEN`)로 바꿨고, 두 스크립트 주석에서 내부 작업 호칭을 지웠습니다.
- **공개하면서 고친 것**: `rag-score.mjs` 의 조문 대조가 부분 일치(`includes`)여서 기대가 `제13조`일 때 `제13조의2`도 적중으로 셀 수 있었습니다. 정확 일치로 고쳤습니다. 아래 결과 1 의 수치는 **고치기 전 코드로 잰 기록**이고, 이 차이가 36/52 에 영향을 줬는지는 원본 검색 결과가 남아 있지 않아 확인하지 못했습니다(영향이 있었다면 실제 적중은 그보다 낮습니다). 결과 2 의 탐침은 처음부터 정확 일치로 셉니다.

## 지표의 뜻

모두 **검색 단계**의 지표입니다. 최종 생성 답변의 정확도가 아닙니다(`rag-score.mjs` 는 `/law/search` 만 부르고 LLM 을 부르지 않습니다).

| 지표 | 뜻 |
| --- | --- |
| 찾음 | 답이 있는 질문에 검색이 근거를 내놓았는가 |
| 기대 조문 Top-5 적중 | 기대한 조문이 검색 결과 상위 5건 안에 있는가. 기대 조문이 적힌 52문만 센다 |
| 침묵 | 답하지 않아야 하는 질문에 근거를 내놓지 않았는가 |

답이 있는 70문 중 18문은 근거가 별표·고시·기술지침·판례라 조문 번호로 채점할 수 없어 적중 분모에서 뺐습니다.

"답하지 않아야 하는 질문"은 이 시스템이 색인한 산업안전보건 법령 범위에서 근거를 댈 수 없는 질문입니다. 다른 법령이나 자료에도 답이 없다는 뜻은 아닙니다(예: 휴업급여는 산업재해보상보험법에 근거가 있습니다).

## 결과 1 — 쉬운 시험의 점수는 성적이 아니었다

| 지표 | 초안 40문 | 100문 (2026-08-18) |
| --- | --- | --- |
| 찾음 | 28 / 28 | 68 / 70 (97%) |
| 기대 조문 Top-5 적중 | 12 / 13 | 36 / 52 (69%) |
| 침묵 | 12 / 12 | 16 / 30 (53%) |
| 검색 경로 | 임베딩 100% | 임베딩 85 · 키워드 폴백 15 |

초안의 "답하지 않아야 하는 질문"은 환율·점심 메뉴처럼 주제가 아예 달랐습니다.
100문에서는 **안전 주제인데 법령에는 근거가 없는 질문**(산재 보험료, 합의금, 작업복 세탁비 등)으로 바꿨고, 30문 중 14문에 근거를 내놓았습니다.

읽을 때 주의할 점:

- 100문 실행은 임베딩 호출 한도 때문에 15문이 키워드 폴백으로 나갔습니다. 순수한 의미검색 성적이 아니라 **그날 시스템이 실제로 낸 값**입니다. 스크립트는 임베딩 비중이 90% 아래면 이 경고를 스스로 출력합니다.
- 근거를 내놓은 문항을 검색 경로별로 가르려고 다시 잰 실행에서는 16건(임베딩 15 · 키워드 1)이 나왔습니다. 위 표의 14문과는 다른 실행의 값입니다.
- 원인으로 의심한 것(못 찾았을 때 질의를 줄여 다시 묻는 경로)은 그날 한도 소진으로 확인하지 못했고, 확인하지 못했다고 적어 두었습니다.

## 결과 2 — 임계값을 내리면 얻는 것보다 잃는 것이 많다 (2026-08-28)

조건: 로컬 색인(bge-m3 · 1,826행) · 원질의 · 상위 5건 · 기대 조문이 있는 52문. 결과 1 과는 임베딩 조건이 달라 숫자를 직접 비교할 수 없습니다.

| 임계값 | 적중 | 답한 문항 | 틀린 근거로 답한 문항 |
| --- | --- | --- | --- |
| 0.50 | 31 / 52 | 52 | 21 |
| 0.62 | 20 / 52 | 33 | 13 |
| 0.68 | 13 / 52 | 15 | 2 |

0.68 에서 0.62 로 내리면 적중은 7문 늘지만 틀린 근거는 11문 늡니다.
법령 답변에서는 틀린 조문 한 건이 답을 못 하는 것보다 위험하다고 보고 임계값을 내리지 않았습니다.

임계값을 0 으로 내려도 정답 조문이 상위 5건에 드는 문항은 33문이 한계였습니다(질의에 각도 낱말을 얹으면 35문, 상위 20건까지 넓히면 43문).
한계는 임계값이 아니라 검색 방식이 정한다는 뜻이고, 못 찾은 문항은 모두 색인에는 있는데 순위에서 밀린 것이었습니다.

`rag-recall-probe.mjs` 는 조문 번호만 대조합니다. 법령 이름까지 대조하는 것은 `rag-score.mjs` 쪽입니다.

## 결과 3 — 더 빠르고 조금 더 맞히는 모델이 근거 밖 인용은 세 배 (2026-08-28)

같은 100문을 로컬 모델 2종으로 **답변 생성까지** 돌렸습니다(임계값 0.68 · 검색 결과는 두 모델에 동일 · 각 1회).

| 지표 | Qwen3 8B | EXAONE 3.5 7.8B |
| --- | --- | --- |
| 생성 지연 중앙값 | 7.0초 | 4.7초 |
| 답이 있는 70문 중 답변한 문항 | 20 | 21 |
| 기대 조문 적중(답변 본문 또는 검색 근거에 포함) | 12 | 14 |
| 답하지 않아야 할 30문 중 침묵 | 30 / 30 | 30 / 30 |
| 검색 근거에 없는 조문을 인용한 답변 | 2 | 6 |

결정적 승자가 없다고 보고 모델을 바꾸지 않았습니다. 각 1회 실행이라 차이를 확정하기에는 표본이 작습니다.
이 비교에 쓴 실행 스크립트는 이 폴더에 없습니다.

## 한계

- 채점은 조문 번호 대조이고 수동 실행입니다. LLM 판정 기반 평가와 사용자 트래픽 A/B 시험은 하지 않았습니다.
- 수치는 개발·검증 환경에서 잰 값이며 외부 사용자가 쓰는 환경의 성과가 아닙니다.
- 정답 묶음은 한 사람이 쓴 100문입니다. 문항 수가 적어 비율의 오차가 큽니다.
